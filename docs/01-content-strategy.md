# NETS 콘텐츠 전략 v1.1 — 1인 운영, 세미나·소프트웨이브 집중

2026-10-12 · Megan Seo · v1.0(같은 날)을 다듬은 판. 바뀐 점은 맨 아래 「v1.1 변경 사항」에 있다.

10/20~12/31 동안 LinkedIn과 Facebook에 **같은 콘텐츠를 톤만 바꿔 화·목 주 2회** 올린다. 행사 주간에만 1건을 더해 총 23건이다. 게시 계획과 상태·성과는 `data/posts.json`, 화면은 대시보드 「업무」 탭의 달력과 SNS 게시 운영 칸에서 본다. 범위는 국내 시장 한정이다.

## 1. 전략 원칙 — 혼자서 버티는 3가지 규칙

원칙은 '적게 만들고, 많이 쪼개고, 이벤트에 몰아준다'이다. 마케팅 조직이 없던 회사에서 1인이 첫 채널을 여는 상황이므로 꾸준함이 볼륨보다 중요하다.

1. **새로 쓰지 말고 꺼내 쓴다 (Source → Slice).** 회사소개서, IAM&SSO·PASS·SaaS Manager·EntraLinker·NDPM 소개서, KB국민은행·SK하이닉스·금융권 사례, 사전진단 서비스 자료에 최소 30개 포스트 분량이 이미 들어 있다. 슬라이드 1장 = 카드뉴스 1장, 문제 정의 슬라이드 1장 = 포스트 1개로 본다. 게시물마다 원천 자료를 `posts.json`의 `source`에 적어 두었다.
2. **모든 콘텐츠는 세 가지 행동 중 하나로 이어진다.** 세미나 참가 문의, 소프트웨이브 부스 상담 예약, 사전진단 문의. 12월 이후는 행사에서 나온 사진·발표·질문을 다시 쪼개 1~2월 콘텐츠로 쓴다(행사 1회 = 6~8주분 소스).
3. **리듬은 낮게, 끊김은 없게.** 평소 주 2회(화·목 09:00), 행사 주간에만 1건을 더한다. 한 번 만든 포스트는 LinkedIn·Facebook에 같은 날 같은 시간에 올리고 문구만 조정한다. 인스타그램·유튜브·블로그는 2027년 1분기 홈페이지 개편 이후로 미룬다.

## 2. 포지셔닝과 핵심 메시지

한 줄 포지셔닝: **"제로트러스트는 계정·권한·인증에서 시작한다 — 28년간 그 시작점을 만들어온 넷츠."** 제품을 나열하지 않고, 고객이 이미 고민하는 주제(제로트러스트, 내부통제, M365 전환)의 입구에 넷츠를 세운다.

| 층위 | 메시지 | 근거 (출처 자료) |
|---|---|---|
| 핵심 | 인증·계정·권한 한 우물만 판 국내 IAM 전문기업 | 업력 28년, 고객사 250+, 프로젝트 480+ (회사소개서, 사전진단 자료) |
| 기둥 1 — 신뢰 | 가장 까다로운 환경에서 검증됐다 | 통신 3사, SK·롯데·현대차 그룹 IM, SK하이닉스 임직원 약 6만 명·700여 개 업무 |
| 기둥 2 — 제로트러스트 | 실증 사업에서 Identity 축을 맡아왔다 | KB국민은행 KISA 제로트러스트 시범사업(2024·2025), 케이뱅크 ZT 실증(2025) |
| 기둥 3 — 교체 역량 | 외산 솔루션을 대체해온 국산 기술 | IBM·Oracle·CA 등 Win-back 20여 건 (현대자동차, 현대해상, SGI서울보증 등), 특허 14건 |
| 기둥 4 — Microsoft 확장 | M365·Entra 환경의 빈칸을 채운다 | SaaS Manager(라이선스 자동화), EntraLinker(도메인 이행), NDPM(DRM→MIP 전환), MS Solution Partner(2025.09) |
| 행동 유도 | 도입 전에 진단부터 | 계정/권한/인증 사전진단 서비스 (3주, AS-IS 진단 → TO-BE 로드맵) |

톤은 '현업을 아는 선배 엔지니어'다. 공포 마케팅(대형 유출 사고 나열)보다 담당자가 실제로 겪는 장면(퇴사자 계정, 감사 자료 준비, 라이선스 누수)으로 말한다.

> 세미나 기획서의 ISEC 2025 설문(QR 134건)에서 도입 이유 1위는 **운영 관리 효율(87)**, 구매 기준은 **비용(80)·레퍼런스(57)** 였다. 인사이트·제품 게시물은 "보안 강화"보다 "운영 부담이 줄어든다"를 앞에 둔다.

## 4. 채널 운영 — 하나로 만들어 두 채널에

제작은 한 번이고 변환은 건당 15분 안쪽이다. 아래 세 가지를 고정해야 두 채널이 똑같아지거나 작업이 두 배가 되지 않는다.

1. **방향은 LinkedIn → Facebook.** LinkedIn 버전을 먼저 완성하고, Facebook은 줄이고 풀어 쓴다.
2. **같은 날 같은 시간 예약.** 화·목 09:00. LinkedIn 페이지 예약과 Meta Business Suite로 건다.
3. **이미지는 공용, 문구만 다르게.** 1080×1350 세로형 템플릿을 두 채널에 그대로 쓴다.

채널별 톤 차이와 변환 예시는 `docs/02-writing-guide.md`에 있다.

도달은 회사 페이지보다 임직원 개인 계정 공유에서 나온다. 게시 직후 대표·영업·기술영업에 공유 문구 1줄을 보낸다.

## 5. 통합 캠페인 플랜 (23건)

| 단계 | 기간 | 건수 | 흐름 |
|---|---|---|---|
| 1. 채널 오픈·신뢰 쌓기 | 10/20~11/3 | 5 | 회사 소개 → 누수 노트 #1·#2 → SSO → SK하이닉스 사례 |
| 2. 세미나 캠페인 | 11/5~11/26 | 7 | Save the date → 계정 라이프사이클 → 누수 노트 #3 → D-7 아젠다 → KB국민은행 사례 → 당일 현장 → 리캡 |
| 3. 소프트웨이브 | 11/27~12/8 | 4 | 부스 안내 → v13.0 AI 권한 추천(데모 예고) → 현장 → 방문 감사·많이 받은 질문 |
| 4. 마무리 | 12/10~12/31 | 7 | Win-back 사례 → 누수 노트 #4(SoD) → 다크웹 암호 탐지 → 결산 → 누수 노트 #5(2027 키워드) → Top 3 → 연말 인사 |

- 세미나는 **초청형**이다. 세미나 관련 게시물의 CTA는 '등록'이 아니라 **'세미나 참가 문의'** 로 쓴다. 실제 모객은 영업 개별 초청과 초대장(10/27 발송)이 맡고, SNS는 인지와 리캡을 맡는다.
- 행사 당일 게시물(11/24, 12/2)은 바쁘면 다음 날 오전으로 미룬다.
- 사례 게시물 3건(11/3·11/19·12/10)은 게시 14일 전까지 공개 동의가 없으면 같은 날 인사이트 게시물로 바꾼다. 동의 전에는 'A 금융사', '국내 반도체 기업'처럼 익명으로 쓴다.
- 11~12월 게시물은 10/26~30에 일괄 제작해 예약한다. 사후 게시물은 사진 칸만 비워 둔다.
- 모든 링크에 UTM: `utm_source=linkedin|facebook&utm_medium=social&utm_campaign=2026q4&utm_content=<게시물 ID>`.

## 6. 행사 현장 콘텐츠 캡처

행사 당일에 모은 소스가 12월~1월 콘텐츠의 원료다. 사내 1명을 '촬영 담당'으로 지정하고(D-12, 11/17까지) `docs/04-event-capture-checklist.md`를 전달한다.

## 7. 포스트 공식과 템플릿

모든 포스트는 **현업 장면(Hook) → 왜 생기나(Insight) → 넷츠의 방식(Solution) → 숫자·사례(Evidence) → 한 가지 행동(CTA)** 순서로 쓴다.

Canva 템플릿은 4종만 만들어 재사용한다 (1080×1350 세로형, LinkedIn·Facebook 공용).

| 템플릿 | 구성 | 쓰는 필러 |
|---|---|---|
| ① 누수 노트 카드뉴스 | 표지(현업 한 문장) → 문제 → 원인 → 해법 → CTA, 3~5장 | 인사이트, 제품 |
| ② 숫자 카드 | 큰 숫자 1개 + 한 줄 설명 (예: 700여 개 업무, 6만 명) | 사례, 회사 |
| ③ 사례 카드 | 고객사·과제 / 넷츠 구축 / 결과, 1장 | 사례, 제품 |
| ④ 이벤트 공지 | 일시·장소·세션·QR, D-day 배지만 교체 | 이벤트 |

예시 문안은 `docs/02-writing-guide.md`.

## 8. 1인 운영 시스템

평소 주 4~5시간, 행사 주간 주 8시간을 상한으로 둔다. 승인은 한 단계: Megan 작성 → 대표(또는 지정 1인) 확인, **24시간 내 회신 없으면 게시**. 고객사 실명이 들어간 게시물만 담당 영업을 추가로 거친다.

승인 대기 24시간을 확보하려고 제작 마감을 이렇게 잡는다.

| 요일 | 할 일 | 시간 |
|---|---|---|
| 월 | 목요일 게시물 문구·이미지 제작, 승인 요청 | 1.5시간 |
| 화 09:00 | 게시물 게시(예약), 임직원 공유 요청 메시지 | 0.5시간 |
| 목 09:00 | 게시물 게시(예약) | 0.5시간 |
| 금 | 다음 주 화요일 게시물 제작·승인 요청, 댓글 응대, 수치 기록, 다음 주 소재 확인 | 2시간 |

Claude Code 명령: 월요일 `/weekly-plan`, 초안 `/draft-post p07`, 금요일 `/friday-log`.

## 9. KPI

첫 12주는 팔로워 수보다 'SNS가 행사와 영업에 기여했는가'를 본다. 채널이 새로 열리므로 목표치는 W4 수치를 기준선으로 잡은 뒤 확정한다.

| 구분 | 지표 | 측정 방법 | 목표 |
|---|---|---|---|
| 운영 | 게시 이행률 | 대시보드 자동 계산 | 90% 이상 |
| 행사 기여 | SNS 경유 세미나 참가 문의 수 | 문의 폼 '알게 된 경로' + UTM | W4 후 확정 |
| 행사 기여 | 소프트웨이브 사전 상담 예약 수 | 예약 폼 유입 경로 문항 | W6 후 확정 |
| 리드 | 사전진단·도입 문의 수 | 문의 폼 유입 경로, 영업팀 공유 | 12월 말 집계 |
| 채널 | 팔로워 수 | 매주 금요일 기록 | 추이만 본다 |
| 콘텐츠 | 게시물별 참여율 (반응+댓글+공유 ÷ 노출) | 플랫폼 통계 | 필러별 비교 → 2027 Q1 비중 조정 |

세미나 기획서의 'LinkedIn 도달 3,000회'는 참고값으로만 두고 SNS 목표로 쓰지 않는다.

## 10. 리스크와 먼저 결정할 것

대시보드 「업무」 탭의 확인·결정 항목(D-01~D-14)과 같다.

- **고객사 실명·로고 공개 범위.** 사례 자료는 영업용이다. 공개 게시는 고객 동의가 필요하다. KISA 시범사업처럼 이미 공개된 건도 공개 범위를 영업과 확인한다. (D-07, 10/20)
- **자료 간 숫자 통일.** 인원 155명/180+, 업력 27년/28년이 섞여 있다. SNS는 28년·250+·480+만 쓴다. (D-02)
- **'국내 IAM 1위' 표현.** 근거가 없으면 '250개 고객사가 선택한'으로 대체한다. (D-03)
- **세미나 날짜·장소.** 2026-10-13 확정: 11/24(화), 엘타워. (D-05 완료)
- **링크 도착지.** 홈페이지 개편 전이므로 세미나 참가 문의·부스 상담 예약·사전진단 문의를 받을 폼을 먼저 만들고, '알게 된 경로' 문항을 넣는다. (D-09, D-10)
- **개인정보.** 세미나·전시 폼의 수집·이용 동의 문구는 LD-1에서 10/27 전 확정한다.
